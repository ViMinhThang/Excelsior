Layered Architecture

The application is organized into four distinct layers with unidirectional dependencies. Each layer has a single responsibility and depends only on the layers below it.

┌─────────────────────────────────────────────────────┐
│                  PRESENTATION LAYER                  │
│              Ink / React TUI (src/tui/)              │
│  Screens · Components · Hooks · Context Providers   │
├─────────────────────────────────────────────────────┤
│                  PROJECTION LAYER                    │
│           Event → Display Block transforms           │
│         (src/lib/projection/projectEvents.ts)        │
├─────────────────────────────────────────────────────┤
│                    AGENT LAYER                       │
│        AI model · Tools · Sub-agent orchestration    │
│             (src/agent/agent.ts, tools/)             │
├─────────────────────────────────────────────────────┤
│                 INFRASTRUCTURE LAYER                 │
│    Event bus · Sessions · SQLite persistence · DB    │
│        (src/lib/runtime/ · persistence/ · db/)       │
└─────────────────────────────────────────────────────┘

Layer 1: Infrastructure

Event Bus (src/lib/runtime/bus.ts)

A typed pub/sub event bus that serves as the foundational communication primitive. Three bus instances exist:

BusChannelPurpose
confirmBus"confirm"Tool execution approval (write/edit/runCommand)
subAgentBus"sub-agent"Sub-agent lifecycle events (spawned/output/done)
AgentSession.bus"session"Agent event stream (per-session)

All buses route through a global EventBusHub for unified observability. Any code can subscribe via observeHub() to receive { channel, event, data } messages from all buses.

Event Types (src/lib/runtime/events.ts)

The AgentEvent discriminated union is the single source of truth for all agent interactions:

Event TypeDataDescription
session-start{}Fired when a session begins streaming
user-input{ content }User submitted a message
text-delta{ delta }Incremental assistant text output
tool-call-start{ toolName, toolArgs, toolCallId }Agent invoked a tool
tool-call-end{ toolCallId, result, status, toolName, toolArgs }Tool execution complete
child-session-attached{ childSessionId, parentToolCallId, role }Sub-agent session created
error{ message }Non-fatal error during agent execution
session-end{ cancelled }Session terminated (natural or cancelled)

AgentSession (src/lib/runtime/agentSession.ts)

Core reactive session class that:

  • Emits typed events via its internal bus
  • Maintains an immutable event snapshot (frozen events array)
  • Supports cancellation via AbortController
  • Provides a useSyncExternalStore-compatible subscription API for React integration
  • Debounces listener notification via setTimeout(0) microtask batching

Persistence (src/lib/persistence/eventPersistence.ts)

SQLite-backed persistence with WAL mode for concurrent read/write:

sessions (id, started_at, updated_at, metadata)
agent_events (id, session_id, sequence, type, timestamp,
              data, parent_event_id, related_tool_call_id)
settings (key, value)
error_logs (id, message, stack, timestamp)

An in-memory LRU write-through cache (max 10 sessions) decouples UI reads from database writes. Events are both persisted to SQLite and written to the cache, so loadSessionEvents() returns cached data when available.

Layer 2: Agent

Agent Factory (src/agent/agent.ts)

The createAgent() factory builds a ToolLoopAgent with:

  • The DeepSeek V4 Flash model configured with the user's API key (or DEEPSEEK_API_KEY env var)
  • A system prompt generated by buildSystemPrompt() with tone scaling rules
  • Filesystem tools (ls, view, write, edit, glob, grep) from the tool registry
  • Optional extra tools (e.g., spawnSubAgent, gitDiff) passed by callers

System Prompt (src/agent/prompt.ts)

The prompt defines three intensity modes that the agent self-selects based on task complexity:

ModeWhenStyle
LIGHTGreetings, quick questions, tiny editsCasual, brief, one-liner responses
MODERATEFeature additions, single-file changesClear and direct, short plan if needed
INTENSIVEMulti-file refactors, architecture, deep debuggingStep-by-step plan, thorough, production-quality code

Layer 3: Projection

The projection layer (src/lib/projection/projectEvents.ts) transforms raw event streams into UI-consumable display blocks. It implements a pure reducer pattern:

createProjectionState() → state
  reduceProjectionEvent(state, event) → void  (mutates in place)
  flushProjectionState(state) → DisplayBlock[]

Two parallel projections exist:

  • groupEventsForDisplay → DisplayBlock[] for the TUI
  • projectEventsToAIHistory → conversation history for model context memory

Layer 4: Presentation

The TUI is a tree of Ink/React components organized as:

ErrorBoundary
  └─ ReviewProvider (composes PR + ReviewSession + SubAgent)
      └─ NavigationProvider (screen stack)
          └─ Router (dispatches screen)
              ├─ ChatScreen    (main interaction)
              ├─ SettingsScreen (API configuration)
              ├─ ReviewScreen  (PR browser/review/results)
              └─ ErrorScreen   (fatal error)

Five context providers manage shared state: NavigationContext, PRContext, ReviewSessionContext, SubAgentContext, and the composite ReviewContext. Sixteen React hooks implement the application logic with clear separation of concerns.

Dependency Graph

Presentation (tui/)
  ├── depends on → Projection (lib/projection/)
  ├── depends on → Agent (agent/)
  │   └── depends on → Infrastructure (lib/runtime/, lib/persistence/, db/)
  └── depends on → Infrastructure (lib/runtime/, lib/persistence/, db/)

No layer depends on a layer above it. The Infrastructure layer has zero knowledge of Ink, React, or AI models.
