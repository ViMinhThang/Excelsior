Evolution: Message Model → Event Stream

A ground-up rewrite of the data layer. Every file that touched the old Message type was replaced. The result is a foundation that scales to sub-agents, replay, and observability.

2. Eliminated Hacks

These are the specific code patterns that motivated the migration. Each was a symptom of forcing a continuous stream into a discrete-message abstraction.

  • currentId = null (was in createStreamCallbacks) — A mutable tracking variable reset at tool-call boundaries to force a new assistant message object. The projection function replaces this: it naturally splits text at tool-call-start events.
  • toolBuffer — Accumulated parallel tool calls into an array to stuff into a single Message.toolCalls field. Events are naturally parallel; the message shape was not.
  • "spawnSubAgent" string-matching in 4 files — useChatSenderUtils.ts, toolDisplay.ts, ChatHistory.tsx, ToolMessage.tsx all checked toolName === "spawnSubAgent" to add special display logic. Now sub-agents are a native DisplayBlock.type.
  • assistantMessages[] + toolMessagesToPersist[] — Two separate arrays maintained in createStreamCallbacks solely for the onFinish flush to persistMessage. The event log eliminates the need to track "what to persist" separately from "what happened."
  • onTextDelta(fullText) — Passed the entire accumulated text on every event, making it impossible to distinguish "what changed" from "what's the total." Now passes { delta } only.
  • session-start / user-input double-emission — Both useChatSender and agentStream.ts were emitting user-input for the same message, causing duplicate user blocks. The fix removed the duplication from agentStream.ts.
  • tool = null without flushTool() — In projectEvents.ts, tool-call-end set tool = null directly, bypassing flushTool(). The tool-call DisplayBlock was never pushed into the output, causing tool messages to appear briefly and disappear.

3. File-by-File Change Log

Created

src/lib/eventTypes.ts created

AgentEvent — immutable execution fact. Session — metadata wrapper. DisplayBlock — UI projection type (user | assistant | tool-call | sub-agent), never persisted. SubAgentDisplayState — runtime state for sub-agent detail view.

src/lib/agentSession.ts created

AgentSession class — owns event bus, append-only log, useSyncExternalStore API. Replaces createStreamCallbacks entirely.

src/lib/eventPersistence.ts created

Replaces chatPersistence.ts. Persists sessions + events to sessions and agent_events tables. Includes projectEventsToAIHistory() for AI SDK context construction.

src/lib/projectEvents.ts created

groupEventsForDisplay(events) → DisplayBlock[]. The pure projection function that replaces all the stateful closure bookkeeping.

Rewritten

src/lib/agentStream.ts rewritten

Accepts (agent, messages, session: AgentSession, signal). Calls session.emit() for each stream part. No return value, no internal state, no callbacks.

src/tui/hooks/useChatSender.ts rewritten

Creates AgentSession, attaches persistence bus subscriber, fires streamAgentResponse without awaiting. sendMessage returns AgentSession | null synchronously.

src/tui/hooks/useChatHistory.ts rewritten

Uses useSyncExternalStore to subscribe to the active session. Deduplicates events across sessions via event-ID filter. Handles session transitions (completed session events preserved in persistedEvents).

src/tui/hooks/useChatScreenState.ts rewritten

handleSubmit calls sendMessage synchronously, attaches session via attachSession. Added submittingRef guard against double-submit race conditions.

src/tui/components/chat/ChatHistory.tsx rewritten

Uses Ink’s <Static> component with LIVED_TAIL = 3. Frozen blocks render once and never re-render. Last 3 blocks remain dynamic for streaming updates.

src/tui/hooks/useReviewOrchestrator.ts rewritten

Creates AgentSession, subscribes to session bus, passes session to streamAgentResponse.

Deleted

src/tui/lib/chatPersistence.ts deleted

Contained persistMessage(), loadMessages(), getMessageCount() operating on the old observation table. Replaced by eventPersistence.ts.

src/__tests__/chatPersistence.test.ts deleted

Tested the deleted chatPersistence module.

4. Database Schema Evolution

Old: observation table

observation (
  id            INTEGER PRIMARY KEY,
  message_id    TEXT,
  role          TEXT NOT NULL,    -- "user"|"assistant"|"tool"
  content       TEXT NOT NULL,
  metadata      TEXT,             -- JSON blob
  timestamp     DATETIME
);

One row per "message." No session grouping. No event ordering beyond timestamp. Tool metadata stuffed into a JSON blob. The role column stored a mapped value ("tool" instead of "tool-call").

New: sessions + agent_events

sessions (
  id          TEXT PRIMARY KEY,
  started_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL,
  metadata    TEXT               -- JSON
);

agent_events (
  id                  TEXT PRIMARY KEY,
  session_id          TEXT NOT NULL,
  sequence            INTEGER NOT NULL,
  type                TEXT NOT NULL,
  timestamp           TEXT NOT NULL,
  data                TEXT NOT NULL,       -- JSON
  parent_event_id     TEXT,                -- nesting
  related_tool_call_id TEXT               -- correlation
);

CREATE INDEX idx_agent_events_session
  ON agent_events(session_id, sequence);

Each session = one user interaction → agent response cycle. Events are ordered by sequence, immutable, and self-describing. Parent/child via parent_event_id enables execution trees. Indexes enable efficient session replay.

7. Benefits

No more currentId = null

The projection naturally splits assistant blocks at tool-call boundaries. The hack was a symptom of forcing a stream into a message model.

No tool-name string-matching

Sub-agents are a native DisplayBlock type. Four files no longer check === "spawnSubAgent".

Independent subscribers

React, persistence, and debugger subscribe to the session bus independently. No callback threading, no rewiring to add a new subscriber.

Deterministic replay

Same events → same display blocks. Enables snapshot testing, time-travel debugging, and reproducibility.

Session-scoped isolation

Each execution owns its bus and event log. No global state, no session-ID filtering, no cross-session leaks.

Event store foundation

Supports future needs: multiple concurrent sessions, background agents, pause/resume, execution trees, and observability tooling.

Stable terminal rendering

Batched React notifications reduce re-renders from hundreds-per-second to one-per-microtask-batch. Ink <Static> freezes completed content, preventing scroll jank.

Clean upgrade path

Sub-agents can adopt the same AgentSession model with minimal changes. The review orchestrator already uses it.
