How Excelsior works

Excelsior is a terminal coding assistant built with Ink, React, the AI SDK, DeepSeek, SQLite, and JSONL event logs. Its core idea is simple: a user message becomes an event-driven agent run; the run streams events; projections turn those events into UI blocks and future model history; persistence stores enough state to restore complete turns. Plan/Act mode keeps exploration separate from mutation, and write/edit confirmations show diffs before disk changes.

Runtime model

The runtime is event-first. `AgentRun` owns ordered immutable events, `RunOrchestrator` streams the model, and `RunRecorder` persists every completed turn checkpoint.

UI model

The TUI is a React/Ink shell. `AgentManager` is the observable store consumed by hooks and rendered by `ChatScreen`, panels, and focused components.

Feature model

Slash commands are feature-owned. Each feature owns its command definitions, panel UI, and helper code, then joins the app through one registry. `/mode` is implemented the same way.

Key Design Principle

Excelsior keeps interactive complexity manageable by separating event production, event persistence, and event projection. The agent runtime does not render UI. The UI does not parse raw model streams. Projection code is pure and deterministic, so persisted history and live streaming can be merged with the same rules.
