Features and tools

How user capabilities are added

Excelsior has two extension surfaces: app features and agent tools. Features define slash commands and UI panels. Tools are AI-callable functions exposed to the model with workspace bounds, Plan/Act mode, confirmations, cancellation, diff previews, and output formatting.

Feature-Owned Slash Commands

Features implement the `AppFeature` contract: an id, command definitions, and optional panels. The registry validates uniqueness and supplies command lookup, panel lookup, autocomplete data, and grouped help text. 

AppFeature
  id: "session"
  commands: [CommandDefinition]
  panels: [FeaturePanelDefinition]

Agent Tool Surface

`createAgent()` builds a `ToolLoopAgent` with base file tools and any extra tools supplied by `ChatService`. `createFileTools(ctx)` registers shell, file, listing, viewing, editing, globbing, and ripgrep search tools.

Read tools

view, ls, glob, and ripgrep inspect files inside the workspace.

Write tools

write and edit validate paths, block in Plan mode, and request confirmation with a unified diff in Act mode.

Shell tool

runCommand runs executables with structured args, blocks dangerous patterns, blocks write-like commands in Plan mode, and confirms them in Act mode.

Plan/Act Mode

Plan mode is the startup default. It is meant for inspection, reasoning, and asking clarifying questions before changing files. Act mode allows mutation, but existing confirmations still apply. The mode is stored in TUI state for v1, exposed through FeatureRuntimeContext, and passed into every run through ToolContext.

Mode Allowed Blocked or confirmed
Plan view, ls, glob, ripgrep, safe runCommand checks. write, edit, and write-like runCommand return a clear blocked result.
Act All normal tool behavior. write and edit show a diff in the confirmation panel before applying changes.

Tool Safety Flow

Sub-Agent Tool

`spawnSubAgent` is an extra tool injected by `ChatService`. It creates a child `AgentRun`, passes down the parent confirmation and cancellation context, starts a focused agent with role-specific instructions, records child events to the same session, and emits run-scoped sub-agent notifications for the owning manager.

Sub-agents should be used for bounded specialist analysis such as security review, bug hunting, style review, or infrastructure review. The sub-agent instructions explicitly prohibit further delegation to avoid nested agent trees.

Adding A New Feature

  1. Create an `AgentCommand` entry in `packages/agent-host/src/commands.ts`.
  2. Add command definitions with `name`, `description`, optional `usage`, and `execute(args, context)`.
  3. If the feature needs UI, add a panel component and register it under `panels`.
  4. Add the feature to `the command registry in `packages/agent-host/src/commands.ts`.
  5. Add registry and behavior tests.

Adding A New Tool

  1. Place implementation under `packages/agent-host/src/agent/tools` and expose a `createXTool(ctx)` factory.
  2. Validate all file paths before any read/write operation.
  3. Check `ctx.mode` before mutation; Plan mode must return the shared blocked message.
  4. Use `ctx.confirm.request()` for write-like actions, including diff metadata for file writes/edits.
  5. Respect `ctx.abortSignal` for long-running work.
  6. Register it in `createFileTools()` or inject it as an extra tool from `ChatService`.
