Where the important behavior lives

This page is a practical map for reading or changing Excelsior. It explains what each major file is responsible for, how data enters and leaves it, and what assumptions to preserve when editing it.

Boot And App Shell

src/index.ts

Starts the process. It initializes the database, renders the Ink app, and registers global crash logging for uncaught exceptions and unhandled rejections.

Important detail: database initialization also creates the persistence directory for file-backed SQLite databases.

apps/tui/src/app.tsx

Composes `ErrorBoundary`, `NavigationProvider`, and `Router`. It is intentionally tiny because most behavior belongs to screens, hooks, and managers.

Router.tsx

Maps `chat` and `settings` screens to components and owns global shortcuts such as `Ctrl+C` exit and `Ctrl+S` settings navigation.

NavigationContext.tsx

Maintains a bounded screen history. It gives feature commands a simple `navigate(screen)` and `goBack()` API.

Chat UI Composition

File Responsibility Inputs Outputs
ChatScreen.tsx Renders the visible chat screen: header, history, sub-agent detail, active feature panel, input, diff-aware confirmation panel, suggestions, footer hints, and current mode. Return model from `useChatScreenState`. Ink elements only.
useChatScreenState.ts Composes manager state, input history, sub-agent navigation, command autocomplete, command results, feature context, and keymaps. `useAgentManager`, navigation context, feature registry. A stable view model for `ChatScreen`.
ChatHistory.tsx Renders projected blocks using `Static` for frozen blocks and live components for current blocks. `ProjectedBlock[]`. User, assistant, tool-call, and sub-agent rows.
SafeTextInput.tsx Custom controlled input behavior for terminal editing, command entry, and shortcut-safe typing. Ink input events. Input state updates and submit callbacks.

Application Services

AgentManager

`AgentManager` is the center of the UI data model. It stores sessions, persisted events, live events, active run handle, child runs, loading state, current Plan/Act mode, sub-agent event subscriptions, and the latest computed snapshot. The TUI should not assemble this state by itself; it should ask the manager. 

send(content)
  ensure/create session
  build AI history from projections
  start ChatService run with current mode
  attach run subscriptions
  notify UI

The manager also handles session switching. It cancels active work before switching, clears visible persisted events, loads completed events from JSONL, then recomputes display blocks.

ChatService

`ChatService` is the boundary between app state and runtime creation. It builds the final message array, creates the agent with base file tools plus `spawnSubAgent`, calls `startRun`, emits the visible `user-input` event, and persists session metadata. It also forwards the current mode so tools and the system prompt agree about Plan versus Act behavior.

Keep model/provider details here or below. Higher UI layers should not know that the current model is DeepSeek or that tools are implemented through the AI SDK.

Runtime Internals

AgentRun

Mutable event source for one run. It assigns sequence numbers, creates immutable events, broadcasts them through a bus, stores snapshots, debounces UI notifications, and cancels via abort controllers.

RunOrchestrator

Starts `streamAgentResponse`, records emitted events through `RunRecorder`, and returns a `RunHandle` with `cancel()` and `done`.

agentStream.ts

Translates AI SDK stream parts into domain events: text deltas, tool-call starts, tool-call ends, errors, and run end. It also retries transient API failures.

events.ts

Defines the event schema and `makeEvent()`. Event ids are UUID-backed, and event objects include causation/correlation metadata for replay and debugging.

Mode And Tool Safety Internals

packages/agent-host/src/lib/runtime/agentMode.ts

Defines the `plan | act` mode type, display formatting, and the shared Plan-mode blocked message returned by mutating tools.

packages/agent-host/src/commands.ts

Owns `/mode`, `/mode plan`, and `/mode act`. The keyboard toggle is wired in `useChatScreenState` through the same manager methods.

packages/agent-host/src/lib/diff/unifiedDiff.ts

Generates compact unified diffs for file creation, overwrite, and targeted edit confirmations without adding a dependency.

packages/agent-host/src/lib/runtime/confirmTypes.ts

Defines the structured confirmation payload: tool name, args, optional file path, action, and diff text.

Persistence Internals

File What it owns Notes
db.ts SQLite connection, table creation, lightweight migrations, settings, error logging. Creates the parent data directory before opening the DB.
eventPersistence.ts Session metadata CRUD and bridge functions to the default recorder. Session deletion removes SQLite row and schedules JSONL deletion.
jsonlEventStore.ts Append/load/delete JSONL files under `data/sessions`. `loadSessionEvents()` trims to the last `TURN_COMPLETE` checkpoint.
runRecorder.ts The public event persistence abstraction used by runtime code. Use this boundary for event persistence changes.

Projection Internals

Projection is the codebase's reducer layer. It consumes ordered events and produces either UI blocks or model history. This layer is pure: no file system, no React, no network.

projectEvents.ts

Builds display blocks. It buffers assistant text, flushes tool calls, attaches child run state to sub-agent blocks, and freezes terminal blocks.

projectHistory.ts

Builds the compact AI history for future turns. Tool results become assistant messages with `[Tool: name(args)]` labels.

projectionMerger.ts

Merges persisted and live events, deduping by id. Live events win when a run is active; parent-event child events are filtered out of parent display.

projectChildren.ts

Converts child run events into sub-agent state: latest line, full output, tool-call list, output parts, timing, and status.
