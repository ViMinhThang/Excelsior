Running and maintaining Excelsior

This page covers local startup, environment variables, persistent files, tests, build commands, and the operational assumptions that matter when you change the runtime.

Local Commands

Command Purpose When to run
npm run dev Runs the TypeScript entry point through `tsx`. During local development.
npm test Runs the Vitest test suite. After behavior changes.
npm run build Runs TypeScript compilation to `dist`. Before shipping or after type-level refactors.
npm start Runs the compiled JavaScript entry point. After `npm run build`.

Environment And Settings

DEEPSEEK_API_KEY

Provider key used by `createAgent()`. The app first checks stored settings through `getSetting("DEEPSEEK_API_KEY")`, then falls back to the environment variable.

GITHUB_TOKEN

Optional token for PR review commands and comment posting. GitHub helpers live under `packages/agent-host/src/lib/github`.

EXCELSIOR_DB_PATH

Overrides the SQLite metadata database path. Useful for tests and isolated runs.

EXCELSIOR_SESSIONS_DIR

Overrides the JSONL session event directory. Tests also use exported setters for isolation.

Operational Invariants

Completed restore is checkpoint-safe

Normal restore loads only through the last `TURN_COMPLETE`. Do not change that unless the crash recovery model changes too.

Tools stay workspace-bounded

Filesystem tools must validate path or pattern boundaries before touching disk. Plan mode blocks mutation; Act mode writes still require confirmation.

Diffs precede file mutation

`write` and `edit` should compute confirmation diffs after validation and before applying changes. Missing or non-unique `oldText` should fail before approval.

Cancellation propagates

Parent cancellation should abort active streams, child runs, and long-running tool work through `AbortSignal`.

Projection remains pure

Projection functions should stay deterministic and side-effect free, because they serve both live display and replay.

Debugging Checklist

  1. If UI is wrong but JSONL is correct, inspect `packages/agent-host/src/lib/projection` and chat components.
  2. If restored history is missing, inspect `TURN_COMPLETE` placement and `loadUntilLastCheckpoint()`.
  3. If a tool acts oddly, inspect the tool factory and `ToolContext` propagation.
  4. If Plan/Act behavior is wrong, inspect `AgentManager` mode state, `ChatService.submitUserTurn()` options, and `createToolContext()`.
  5. If sub-agent rows leak between runs, inspect `SubAgentEventSink` plumbing and manager lifetime.
  6. If commands do not route, inspect `getSubmittedCommand()`, `handleCommand()`, and the feature registry.

Maintenance Notes

Runtime files under `data/` are local state, not source. The codebase should remain testable with temporary DB and session paths. When adding persistence behavior, prefer test-only configuration hooks over touching global runtime data.
