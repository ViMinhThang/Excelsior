Data Flow

Understanding how data moves through Excelsior is key to understanding the application architecture. This section covers the main flows: chat messaging, PR reviews, and agent orchestration.

Chat Message Flow

When a user sends a message in the chat screen, data flows through several components:

1

User Input

User types a message in ChatInput and presses Enter. The handleSubmit function in useChatScreenState is triggered.

// useChatScreenState.ts
const handleSubmit = useCallback(async () => {
  const trimmed = inputRef.current.trim();
  if (!trimmed) return;

  // Check for slash commands first
  const isCommand = await handleCommand(trimmed, commandContext);
  if (isCommand) { setInput(""); return; }

  // Send to chat
  setInput("");
  sendMessage(trimmed);
}, [isLoading, navigate, goBack, sendMessage, ...]);
2

Message Persistence

The message is immediately persisted to SQLite and added to the UI state via useChatHistory.

// useChatSender.ts - sendMessage function
const userMsg: Message = { 
  id: generateId(), 
  role: "user", 
  content: trimmed, 
  timestamp: new Date().toISOString() 
};
append(userMsg);           // Add to UI state
persistMessage(userMsg);   // Save to SQLite
3

Agent Processing

useChatSender creates an agent with tools and streams the response. The createStreamCallbacks utility handles real-time updates.

// useChatSender.ts
const agent = createAgent(undefined, { spawnSubAgent: spawnSubAgentTool });
await streamAgentResponse(agent, history, streamHandler.callbacks, abortController.signal);
4

Real-time UI Updates

As the agent streams responses, callbacks update the message in real-time. Tool calls and results are displayed as they occur.

// streamAgentResponse in agentStream.ts
for await (const rawPart of stream.fullStream) {
  if (part.type === "text-delta") {
    fullContent += delta;
    callbacks.onTextDelta(fullContent);  // Real-time text update
  } else if (part.type === "tool-call") {
    callbacks.onToolCall(toolName, toolArgs, toolCallId);
  } else if (part.type === "tool-result") {
    callbacks.onToolResult(toolCallId, getToolResult(part));
  }
}
5

Final Persistence

Once the stream completes, the final assistant message is persisted to the database for session continuity.

Tool Confirmation Flow

When the agent wants to run a potentially dangerous command, user confirmation is required:

// runCommand.ts - isWriteCommand pattern matching
const WRITE_PATTERNS = [
  /rm\s+/i, /git\s+(commit|push|reset)/i,
  /npm\s+(install|publish|remove)/i,
  /\b(Set-Content|Remove-Item|Move-Item)\b/i,  // PowerShell
  // ... more patterns
];

function isWriteCommand(command: string): boolean {
  return WRITE_PATTERNS.some((pattern) => pattern.test(command));
}

// In execute:
if (isWriteCommand(command) && confirmBus.listenerCount > 0) {
  const approved = await confirmBus.requestConfirmation({
    callId: randomUUID(),
    toolName: "runCommand",
    args: JSON.stringify({ command }),
  });
  if (!approved) return "Denied by user.";
}

State Management Patterns

1. React Context for Global State

Application-wide state (navigation, review sessions, sub-agents) uses React Context:

// NavigationContext.tsx - Simple history-based navigation
export const NavigationProvider = ({ children }) => {
  const [history, setHistory] = useState(['chat']);
  const currentScreen = history[history.length - 1] || 'chat';

  const navigate = useCallback((screen: Screen) => {
    setHistory(prev => [...prev, screen]);
  }, []);

  const goBack = useCallback(() => {
    setHistory(prev => prev.length > 1 ? prev.slice(0, -1) : prev);
  }, []);

  return (
    
      {children}
    
  );
};

2. Event Bus for Cross-Cutting Concerns

Sub-agent events and tool confirmations use an event bus pattern to decouple components:

// spawnSubAgent.ts - SubAgentBus
export function createSubAgentBus() {
  const listeners = new Set();

  return {
    subscribe(listener: SubListener) {
      listeners.add(listener);
      return () => { listeners.delete(listener); };
    },
    emitSpawned(args) { /* notify all listeners */ },
    emitOutput(args) { /* streaming output updates */ },
    emitDone(args) { /* completion notification */ },
  };
}

3. Refs for Mutable State

Values that need to be read synchronously in callbacks use refs:

// useChatSender.ts
const abortRef = useRef(null);
const isLoadingRef = useRef(isLoading);
isLoadingRef.current = isLoading;  // Keep in sync

const cancel = useCallback(() => {
  cancelledRef.current = true;
  abortRef.current?.abort();  // Access latest value in callbacks
}, []);

4. Database Proxy for Lazy Initialization

The database uses a lazy-loading proxy to avoid initialization issues:

// db/index.ts
export const db = new Proxy({} as Database.Database, {
  get(_, prop, receiver) {
    return Reflect.get(getDb(), prop, receiver);  // Creates DB on first access
  },
});

Error Handling Flow

Errors are handled at multiple levels to ensure graceful degradation:

⚠️

Error Boundary: The TUI wraps all content in an ErrorBoundary component that catches React rendering errors and displays them in a user-friendly ErrorScreen.

// index.ts - Global error handlers
process.on('uncaughtException', (err) => {
  logError(`Uncaught Exception: ${err.message}`, err.stack);
  process.exit(1);
});

process.on('unhandledRejection', (reason) => {
  logError(`Unhandled Rejection: ${String(reason)}`);
  process.exit(1);
});

// Agent streaming errors are caught and displayed
